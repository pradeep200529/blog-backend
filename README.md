# Margin Notes

A responsive full-stack blog application with public reading, account registration and login, and a private author dashboard. Built with Node.js, Express, vanilla JavaScript, SQLite, and Supabase.

## Features

- Browse and read public posts without an account.
- Register and sign in with passwords hashed using Node.js `scrypt`.
- View a private dashboard containing only the signed-in author's posts.
- Create, edit, and delete posts, with server-side author checks.
- Revoke the active JWT on logout; protected requests reject revoked tokens.
- Responsive layout, accessible dialogs and forms, and reduced-motion support.
- SQLite for local development; Supabase for managed production persistence.

## Run locally

Requirements: Node.js 22.13 or newer and npm.

```powershell
npm ci
Copy-Item .env.example .env
```

Set `JWT_SECRET` in `.env` to a random value of at least 32 characters, then start the app:

```powershell
npm run dev
```

Open `http://localhost:3000`. The app and API are served from the same origin. By default, SQLite creates `data/blog.sqlite` automatically. The sample `CLIENT_ORIGIN` is only needed for a separate frontend origin.

## Production database

For production, use Supabase so blog data and revoked tokens persist independently of the web service. Run this SQL in the Supabase SQL Editor:

```sql
create table public.users (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  email text not null unique,
  password_hash text not null,
  created_at timestamptz not null default now()
);

create table public.blogs (
  id uuid primary key default gen_random_uuid(),
  author_id uuid not null references public.users(id) on delete cascade,
  title text not null,
  content text not null,
  excerpt text not null,
  created_at timestamptz not null default now()
);

create table public.revoked_tokens (
  token_id text primary key,
  expires_at bigint not null
);

alter table public.users enable row level security;
alter table public.blogs enable row level security;
alter table public.revoked_tokens enable row level security;
```

Set `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` in the server environment. Keep the service-role key server-side; never expose or commit it. The backend uses the service role to access tables with row-level security enabled.

## Deploy to Render

The repository includes a `render.yaml` Blueprint for a single Render web service. It serves the frontend and API together and expects Supabase for persistent production data.

1. Create the Supabase project and tables using the SQL above.
2. Push the repository to GitHub.
3. In Render, choose **New** then **Blueprint**, and connect the GitHub repository.
4. Enter `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` when prompted. `JWT_SECRET` is generated by the Blueprint.
5. Deploy the service and open the `onrender.com` URL shown in its dashboard.

Render supplies `RENDER_EXTERNAL_URL`, which is used as the default allowed client origin. The free web service may sleep when idle; its first request after sleeping can take longer. The live website URL is assigned by Render after deployment.

## API

Protected endpoints use `Authorization: Bearer <token>`. JWTs use HS256, expire after two hours, and receive unique IDs that are stored on logout for revocation.

| Method | Endpoint | Access | Purpose |
| --- | --- | --- | --- |
| `GET` | `/api/health` | Public | Health check |
| `POST` | `/api/auth/register` | Public | Create an account and issue a JWT |
| `POST` | `/api/auth/login` | Public | Sign in and issue a JWT |
| `GET` | `/api/auth/me` | JWT required | Get the current profile |
| `POST` | `/api/auth/logout` | JWT required | Revoke the current JWT |
| `GET` | `/api/dashboard` | JWT required | Get the current profile and latest 50 authored posts |
| `GET` | `/api/blogs` | Public | List the latest 50 posts |
| `GET` | `/api/blogs/:id` | Public | Read one post |
| `POST` | `/api/blogs` | JWT required | Create a post |
| `PUT` | `/api/blogs/:id` | Author JWT required | Update a post |
| `DELETE` | `/api/blogs/:id` | Author JWT required | Delete a post |

Post creation and update accept `{ "title": "A title", "content": "The post body", "excerpt": "Optional summary" }`. Title and content are required. An omitted excerpt is generated from the first 240 characters of the content. A successful delete returns `204 No Content`.
